 ┃   ### Why this approach?
 ┃
 ┃   Because your backend uses a GraalVM native image, compiling it requires
 ┃   significant CPU and memory (~4–6 GB RAM during native compilation). Render's
 ┃   free tier build environment does not have enough memory to compile GraalVM
 ┃   native binaries reliably.
 ┃
 ┃   The optimal pattern is:
 ┃
 ┃   1. GitHub Actions builds the GraalVM Docker image on GitHub's free runners
 ┃   (which provide 7 GB RAM).
 ┃   2. GitHub Actions pushes the built image to GitHub Container Registry (GHCR) or
 ┃   Docker Hub.
 ┃   3. GitHub Actions triggers a Render Deploy Hook (a simple webhook URL).
 ┃   4. Render pulls the new image and deploys it automatically.
 ┃   ──────
 ┃   ### Step-by-Step Implementation

 ┃   #### 1. Configure the Backend Service on Render
 ┃
 ┃   1. Go to your Render Dashboard and open your backend web service.
 ┃   2. Ensure the service is configured to deploy from an Existing Image (e.g.,
 ┃   ghcr.io/<your-username>/inbox-backend:latest).
 ┃   3. In your service's Settings, scroll down to Deploy Hook.
 ┃   4. Click Create Deploy Hook and copy the generated URL (it looks like
 ┃   https://api.render.com/deploy/srv-xxxxxxx?key=yyyyyyy).
 ┃   ──────
 ┃   #### 2. Add Secrets to GitHub Repository
 ┃
 ┃   In your GitHub repository:
 ┃
 ┃   1. Go to Settings > Secrets and variables > Actions.
 ┃   2. Add a new repository secret:
 ┃       • RENDER_DEPLOY_HOOK: Paste the Render deploy hook URL.
 ┃
 ┃
 ┃   (Note: If pushing to GHCR, GitHub Actions can use the built-in GITHUB_TOKEN
 ┃   automatically, so no external Docker credentials are required.)
 ┃   ──────
 ┃   #### 3. Create the GitHub Actions Workflow
 ┃   Create a workflow file at .github/workflows/backend-ci-cd.yml:
 ┃
 ┃     name: Backend CI/CD
 ┃
 ┃     on:
 ┃       push:
 ┃         branches:
 ┃           - main
 ┃         paths:
 ┃           - 'backend/**'
 ┃           - '.github/workflows/backend-ci-cd.yml'
 ┃
 ┃     env:
 ┃       REGISTRY: ghcr.io
 ┃       IMAGE_NAME: ${{ github.repository }}-backend
 ┃
 ┃     jobs:
 ┃       build-and-deploy:
 ┃         runs-on: ubuntu-latest
 ┃         permissions:
 ┃           contents: read
 ┃           packages: write
 ┃
 ┃         steps:
 ┃           - name: Checkout Code
 ┃             uses: actions/checkout@v4
 ┃
 ┃           - name: Set up Docker Buildx
 ┃             uses: docker/setup-buildx-action@v3
 ┃
 ┃           - name: Log in to GitHub Container Registry
 ┃             uses: docker/login-action@v3
 ┃             with:
 ┃               registry: ${{ env.REGISTRY }}
 ┃               username: ${{ github.actor }}
 ┃               password: ${{ secrets.GITHUB_TOKEN }}
 ┃
 ┃           - name: Extract Docker Metadata
 ┃             id: meta
 ┃             uses: docker/metadata-action@v5
 ┃             with:
 ┃               images: ${{ env.REGISTRY }}/${{ env.IMAGE_NAME }}
 ┃               tags: |
 ┃                 type=raw,value=latest
 ┃                 type=sha,format=short
 ┃
 ┃           - name: Build and Push Docker Image
 ┃             uses: docker/build-push-action@v5
 ┃             with:
 ┃               context: ./backend
 ┃               file: ./backend/Dockerfile
 ┃               push: true
 ┃               tags: ${{ steps.meta.outputs.tags }}
 ┃               labels: ${{ steps.meta.outputs.labels }}
 ┃               cache-from: type=gha
 ┃               cache-to: type=gha,mode=max
 ┃
 ┃           - name: Trigger Render Deploy Hook
 ┃             run: |
 ┃               echo "Triggering Render deployment..."
 ┃               curl -X POST "${{ secrets.RENDER_DEPLOY_HOOK }}"
 ┃   ──────
 ┃   ### How the Full Flow Works Once Setup is Complete
 ┃
 ┃   1. You push commits to main:
 ┃       • If changes touch frontend/, Vercel detects them and redeploys the frontend
 ┃       automatically.
 ┃       • If changes touch backend/, GitHub Actions triggers automatically.
 ┃   2. GitHub Actions runner:
 ┃       • Builds your GraalVM native Docker image with Docker layer caching.
 ┃       • Tags and pushes the image to GitHub Container Registry (ghcr.io).
 ┃       • Hits Render's webhook endpoint.
 ┃   3. Render:
 ┃       • Detects the webhook trigger, pulls ghcr.io/<your-username>/inbox-
 ┃       backend:latest, and rolls out the new container without any manual
 ┃       intervention.
